# Reasoning context and the introspection trap

> Verified against Pi 0.84.4, `@earendil-works/pi-ai`, Kimi K2.7 Code via `api.kimi.com/coding`.

## The non-obvious fact

Pi correctly forwards assistant reasoning/thinking blocks from turn to turn, but the model may still "know" a fact in its reasoning channel and deny it in the final `text` reply. When debugging context issues, trust the wire payload and session logs, not the model's own claims about what it remembers.

## Two channels

Pi treats reasoning and final answer as separate content streams:

| Channel | OpenAI Completions shape | Anthropic Messages shape | Stored in session JSONL |
|---|---|---|---|
| Final answer | `content` (`text`) or `tool_calls` | `content` block `type: "text"` / `type: "tool_use"` | `assistant.content[]` block `type: "text"` |
| Reasoning | `reasoning_content` field | `content` block `type: "thinking"` with `signature` | `assistant.content[]` block `type: "thinking"` |

Both streams are persisted in the session JSONL and replayed into the next provider request. Pi does not merge or drop them.

## How Pi replays reasoning

### OpenAI Completions path

Source: `node_modules/@earendil-works/pi-ai/dist/api/openai-completions.js`, `convertMessages()`.

- Assistant `thinking` blocks are converted back to the provider field indicated by `block.thinkingSignature` (commonly `reasoning_content`).
- For `opencode-go`, the provider delta field `reasoning` is normalized to `reasoning_content` on both receive and send.
- If `compat.requiresReasoningContentOnAssistantMessages` is true and the model is marked `reasoning`, Pi inserts `reasoning_content: ""` for assistant turns that have no stored reasoning. This is required by some models (Kimi K3, DeepSeek) for multi-turn tool use.

### Anthropic Messages path

Source: `node_modules/@earendil-works/pi-ai/dist/api/anthropic-messages.js`, `convertMessages()`.

- Assistant `thinking` blocks become Anthropic `type: "thinking"` content blocks with their signature.
- `allowEmptySignature: true` (set on `kimi-coding` models) keeps the block as `thinking` even when the signature is empty; otherwise Pi would downgrade it to plain `text`.
- This means reasoning survives round-trips for Kimi K2.7 Code via `api.kimi.com/coding`.

## Why the model can "know" and still say "I don't remember"

Reasoning is generated by the same forward pass as the final answer, but it is not a set of instructions the model must obey. Factors that can make the two channels diverge:

1. **Instruction conflict.** A system instruction like "do not speak your reasoning aloud" can be generalized by the model to "do not treat reasoning as a source of facts for the reply".
2. **Channel separation.** The model sees its past `thinking` blocks as internal monologue, not as user-visible commitments. It may choose to summarize or ignore them in the final `text`.
3. **Anchoring.** The final answer is heavily anchored by the immediately preceding user message and by the system prompt's tone. If that framing says "you do not have access to X", the model may produce "I don't have access" even when X is present in `thinking`.
4. **No true self-knowledge.** Reasoning is text generation conditioned on the prompt, not introspection. It can construct a plausible but wrong theory of its own state.

## Practical debugging

When a model claims it cannot see previous reasoning:

1. Do not accept the claim. Check the artifacts.
2. Run `/payload-trace start` and reproduce the turn. Inspect `req-<seq>-<ts>.json`: the previous assistant message should contain both `text` and `thinking` / `reasoning_content`.
3. Export the session with `outline-reasoning` format (`pi-session-memory`) to see stored `thinking` blocks side-by-side with replies.
4. Use `context-guard` `/context-dump` to inspect the conversation array as Pi sees it before the provider request.
5. If the payload contains the reasoning, the issue is model behavior, not Pi context loss.

## When this matters

- Testing whether the agent "remembers" something: put the fact in the `text` channel or ask explicitly for it to be carried into the reply.
- Debugging "ROLE_SW_REQUIRED" or missing context: check dumps, not the model's self-report.
- Avoid relying on reasoning as ground truth about runtime behavior. Use the source code and captured payloads instead.
